<objective>
Build the Phase 1 connector foundation for Plane Demand Hub: health checking, read-only timeline export, natural-language progress preview, write-boundary documentation, and source-traceable verification.
</objective>

<must_haves>
- Plane health can be checked from one command without printing secrets.
- Timeline export uses Plane PostgreSQL only as a read source and emits stable JSONL.
- The export supports a `SINCE` filter for daily/weekly windows.
- The user's first progress case can be parsed into structured events and a Plane change preview.
- Docs clearly state that normal Plane writes go through API-level behavior, not direct SQL.
</must_haves>

  <title>Add Plane health command</title>
  <files>scripts/plane-health.sh</files>
  <action>Create a root-runnable shell script that checks the configured Plane URL, Docker Compose service status, database reachability, and configured release/version basics while redacting secrets.</action>
  <verify>Run `scripts/plane-health.sh` and confirm it exits 0 when Plane is up.</verify>
  <acceptance_criteria>Output includes URL, HTTP status, compose services, and database read check; output does not include `POSTGRES_PASSWORD`, API secrets, or raw env values.</acceptance_criteria>
</task>
