<objective>
Build a local static Gantt sidecar for Plane Demand Hub that renders Plane parent-child task hierarchy, connector lines, blocker/completion/milestone event markers, delivery-summary details, and dense/presentation display modes from existing local exports.
</objective>

<truths>
- Plane remains the source of truth; this phase must not fork or mutate Plane UI internals.
- Normal Plane writes remain API-level or controlled-script gated; this phase is a read/render workflow.
- The new Gantt view is separate from the existing dashboard and should preserve existing dashboard outputs.
- Plane `parent_id` is the authoritative hierarchy source.
- Event marker classification is Plane-native first: labels, state, and `completed_at`.
- Visible task and event summaries default to at most 8 characters.
</truths>

## Must Haves

- D-01: Build a new Gantt view rather than continuing to tune the existing dashboard as the main visualization.
- D-02: Preserve existing dashboard artifacts and add a separate sidecar output, expected as `exports/delivery/gantt.html` plus structured data.
- D-03: Keep the view local-first and static-file friendly unless implementation proves a tiny local server is required.
- D-04: Use Plane `parent_id` as the authoritative multi-level hierarchy source.
- D-05: Preserve task IDs, parent IDs, depth, sibling order, date range, status/progress, owner/labels/modules, and source references in the Gantt model.
- D-06: Parent task bars are clickable expand/collapse controls; collapsed parents keep rolled-up timing/progress.
- D-07: Parent-child connector lines are required and must remain readable through collapse, expand, and horizontal scroll.
- D-08: Blocker, completion, and milestone event markers come from Plane-native labels, state, and `completed_at`.
- D-09: Marker mapping is blocker = red circled cross, completion = green dot, milestone = yellow star.
- D-10: Progress audit events may enrich details but must not override Plane-native marker classification.
- D-11: Clicking a task bar or event marker opens delivery-summary details by default, not a raw audit/debug panel.
- D-12: Detail content prioritizes task title/key, owner if known, state/progress, date range, blocker or milestone summary, next action, and source links.
- D-13: Raw source evidence remains available inside details but secondary to delivery summary.
- D-14: Task bars and event markers show compact default summaries capped at 8 characters, with full text via click or hover detail.
- D-15: Support both high-density table mode and presentation/reporting mode.
- D-16: Default to high-density mode for daily operational scanning.
- D-17: Presentation mode is a toggle or alternate render state with larger rows, clearer labels, and less clutter while preserving the same data.

<threat_model>
## Threat Model

| Threat | Severity | Mitigation |
|--------|----------|------------|
| Generated HTML renders unescaped Plane titles, comments, or progress text | high | Use `html.escape` or JSON-safe embedding for all dynamic strings before inserting into HTML. |
| Gantt generator accidentally writes to Plane or mutates exported source files | high | Keep Phase 6 scripts read/render only; Plane writes remain outside this workflow. |
| Secret paths or environment values leak into generated docs or HTML | medium | Do not read or print `plane.env`, API tokens, or passwords. Include source IDs and issue keys, not secrets. |
| Marker classification misrepresents progress by trusting free-text audit over Plane state | medium | Use Plane labels/state/`completed_at` as primary marker source; use progress audit only for enrichment. |
</threat_model>
